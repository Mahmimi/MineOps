# Deployment Guide

This guide deploys the MineOps Phase 2 runtime foundation to a local k3d cluster with Terraform.

## Prerequisites

- Docker
- k3d
- kubectl
- Terraform
- a Playit secret key

## 1. Create The Local Cluster

```bash
New-Item -ItemType Directory -Force .\.local\k3d\storage
$env:MINEOPS_STORAGE_PATH = (Resolve-Path .\.local\k3d\storage).Path
k3d cluster create --config infra/k3d/local.yaml
```

Confirm access:

```bash
k3d kubeconfig get mineops-local
kubectl cluster-info
kubectl get nodes
```

The kubeconfig generated by k3d should point to:

```text
https://localhost:6550
```

If it does not, recreate the cluster from `infra/k3d/local.yaml`; do not hand-edit kubeconfig as a normal workflow.

## 2. Secrets For Validation

Terraform creates a placeholder `playit-secret` by default and scales Playit to `0` replicas. This keeps clean-room validation reproducible without real Playit credentials.

Do not commit real secret values.

To test Playit with a non-production token later, create a local, ignored `terraform.tfvars` file and set:

```hcl
playit_replicas     = 1
playit_secret_value = "replace-with-non-production-playit-secret"
```

## 3. Review Terraform Variables

Copy the example variables if local overrides are needed:

```bash
cp infra/terraform/terraform.tfvars.example infra/terraform/terraform.tfvars
```

Adjust storage size, Minecraft version, memory, ops, or kubeconfig path as needed.

## 4. Apply Terraform

```bash
cd infra/terraform
terraform init
terraform fmt
terraform validate
terraform plan
terraform apply
```

Terraform manages:

- `mineops` namespace
- `minecraft-data` PersistentVolumeClaim
- `minecraft` Deployment
- `minecraft` Service
- placeholder `playit-secret` Secret
- `playit` Deployment

## 5. Validate Runtime

```bash
kubectl get all -n mineops
kubectl get pvc -n mineops
kubectl logs -n mineops deploy/minecraft
kubectl logs -n mineops deploy/playit
```

The Minecraft Service is configured as `LoadBalancer` for k3d local exposure on TCP port `25565`.

## Important Notes

- Phase 2 does not copy legacy world data.
- A fresh empty world may be created if Minecraft starts before migration.
- Keep replicas at `1`.
- Do not implement scale-to-zero in this phase.
- Do not add Discord bot or controller resources in this phase.
- Keep Playit at `0` replicas unless using a non-production token.
